# 熊猫日历（dsh-panda-calendar）可行性调查报告

> 调查时间：2026-09；方式：桌面调研 + 对候选数据源逐一**实测请求**（状态码 / CORS 头 / 返回结构），而非仅看文档。
> 目标约束：**所有数据源免费、无需 API Key、尽量稳定**；能本地算法算的就不调接口。

---

## 1. 调查范围与结论总览

| 数据块 | 判定 | 采用方式 | 首选来源 | 实测结果 |
| --- | --- | --- | --- | --- |
| 公历 / 农历互转 | ✅ 本地算法 | 内置纯 JS 引擎 | 移植/内嵌 MIT 农历算法（参考 [6tail/lunar-javascript](https://github.com/6tail/lunar-javascript)） | 库无第三方依赖、可在 Node 与浏览器运行 |
| 干支（年/月/日）、生肖 | ✅ 本地算法 | 同上引擎 | 同上 | 由农历/公历推算，非独立数据源 |
| 二十四节气 | ✅ 本地算法 | 同上引擎（天文算法） | 同上 | 可到分钟级；界面按「日」展示 |
| 中国传统节日（春节/清明/端午/中秋…） | ✅ 本地算法 | 农历规则表 + 节气判定 | 自建规则（`农历月日 = 节日`，清明/冬至按节气） | 不依赖网络 |
| 常见外国/国际节日 | ✅ 本地算法 | 固定日期 + 规则（如复活节公历算法、感恩节 11 月第 4 个周四） | 自建规则表 | 不依赖网络 |
| 中国法定节假日 + 调休 | ⚠️ 需年度官方安排 | 联网拉取开源年度数据 + 内置兜底 | **NateScarlet/holiday-cn**（jsDelivr CDN 主、GitHub raw 备） | 2025/2026 年文件实测 200、CORS `*`；2027 为空壳（官方 11 月公布） |
| 用户所在地天气（实时 + 未来 3 天） | ✅ 公开免费接口 | 按经纬度请求 | **Open-Meteo**（open-meteo.com） | 实测 200、CORS `*`、无 key；地理编码中文城市名可用 |
| 自动定位 → 城市 | ✅ 免费链路 | 浏览器定位优先 → IP 兜底 → 手动选择 | navigator.geolocation → ip-api.com → BigDataCloud 反查 | 链路各环节均免费无 key |

**一句话结论：该插件可在「零 API Key」约束下完整实现；联网仅用于两块——① 中国法定节假日年度安排（每年更新一次的数据文件），② 用户所在城市天气。其余全部本地算法离线可用。**

## 2. 分项调查详情

### 2.1 农历 / 干支 / 生肖 / 节气 —— 本地算法可行

- [6tail/lunar-javascript](https://github.com/6tail/lunar-javascript)（MIT License，实测 LICENSE 200）：无第三方依赖的公历/农历/老黄历工具，支持干支、生肖、节气、节日、星座等，浏览器与 Node 均可运行（示例见其 README：`Solar.fromYmd(...).getLunar()`）。
- 结论：将算法内嵌/移植进插件（不依赖运行时 CDN），覆盖用户需求中的「公历、农历、节气、生肖」与问卷追加的「进阶版干支纪年/月/日」。
- 边界：实现时用单元测试钉死常用区间（至少 1900–2100）的正确性，并把农历引擎做成可注入依赖的纯函数模块（沿用诗词插件的可测模式）。

### 2.2 中国法定节假日 + 调休 —— 必须联网更新，数据文件方案

官方每年（通常 11 月前后）公布次年放假与调休安排，**纯算法推不出调休**，因此需要年度数据源。候选实测：

| 候选 | 说明 | 实测 |
| --- | --- | --- |
| **NateScarlet/holiday-cn**（GitHub 开源，自动抓取国务院公告） | 每年一个 JSON：`{year, papers[], days:[{name, date, isOffDay}]}`；调休上班日 = `isOffDay:false` 的条目；含官方公告原文链接 `papers` | jsDelivr：`https://cdn.jsdelivr.net/gh/NateScarlet/holiday-cn@master/2025.json` → **200 / CORS \***；GitHub raw 同样 **200 / CORS \***；2026 年数据已发布（含春节 8 天等），2027 当前为空壳（官方未公布，属正常） |
| timor.tech 免费节假日 API（问卷中你点名考察） | `https://timor.tech/api/holiday/year/2025` 之类 | **服务器侧实测返回 403 已禁止**（可能是反爬 / 区域 / UA 限制；浏览器环境未验证）；不建议作为主源 |
| 聚合数据 / APISpace 等 | 需注册 key | ❌ 违背无 key 约束 |

**方案**：主源 = holiday-cn 年度 JSON（jsDelivr CDN 优先，GitHub raw 兜底；浏览器直连、无 key、CORS 全开）；本地缓存该文件；当某年「未公布/拉取失败」时降级为内置规则表（仅法定节日本身、不含调休）并提示「以官方公布为准」。timor.tech 视后续浏览器实测情况可作第三备选，但**不进主链路**。

### 2.3 天气与定位 —— 免费无 key 链路成立

| 环节 | 候选 | 实测 |
| --- | --- | --- |
| 天气数据（实时 + 3 天） | [Open-Meteo](https://open-meteo.com/) `api.open-meteo.com/v1/forecast` | **200 / CORS \***；支持 `current`（温度/体感/湿度/风速/天气代码）+ `daily` 3 天（最高/最低温、日出日落）+ `timezone=auto`，无需 key |
| 城市搜索 | Open-Meteo Geocoding `geocoding-api.open-meteo.com/v1/search`（`language=zh`） | **200 / CORS \***；返回中文名 + `country_code`/`admin1`/`timezone`；⚠️ 消歧问题：搜「东京」会把江苏镇江的「东京」排在前面 → UI 必须展示国家/地区供选择 |
| 反查城市名（由经纬度 → 城市） | [BigDataCloud](https://www.bigdatacloud.com/) `api.bigdatacloud.net/data/reverse-geocode-client` | **200 / CORS \***、免费无 key、支持 `localityLanguage=zh` |
| 自动定位 | ① 浏览器 `navigator.geolocation`（用户授权，最准）；② 失败兜底 `ip-api.com/json`（免费层仅 HTTP、**200 / CORS \***；dsh web 跑在 `http://127.0.0.1` 时无混合内容问题） | 均实测可用 |
| 位置策略 | 问卷答案：**自动定位 + 手动兜底** + 常用城市列表 | — |

### 2.4 无 key 约束的总体风险评估

- 主要风险不在「有没有 key」，而在**免费接口稳定性与地区可达性**（如国内访问 GitHub raw 不稳）。对策：多源回退链 + 本地缓存 + 内置兜底数据 + 手动刷新按钮，全部沿用在诗词插件中已验证的数据层模式（令牌桶限流、缓存、降级提示）。
- Open-Meteo 面向非商业用途免费；插件本身 MIT 开源、个人使用场景无碍，README 标注数据来源致谢。
